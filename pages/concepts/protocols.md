# 穿透类型

穿透类型决定节点如何接收访问，以及客户端如何把数据交给本地服务。选择时先看本地服务使用的协议，再看是否需要域名、访问密钥或点对点能力。

## TCP

面向连接的通用传输方式。适合 SSH、RDP、VNC、Minecraft Java、数据库和多数不依赖 UDP 的服务。

优点是兼容性好、行为稳定；缺点是所有数据都按 TCP 传输，无法替代真正的 UDP 服务。

## UDP

面向数据报的传输方式。适合部分游戏、语音、实时发现和其他明确使用 UDP 的程序。客户端和节点都必须支持对应的 UDP 转发能力。

## HTTP

用于 HTTP 网站和 HTTP API。通常可以使用域名访问，由节点根据域名把请求转给本地 Web 服务。它不是任意 TCP 服务的通用替代方案。

## HTTPS

用于 HTTPS 网站。证书终止位置、TLS 模式和本地服务是否已经启用 HTTPS 需要按平台和教程配置。不要把 HTTPS 类型简单理解为“给任意端口自动加证书”。

## STCP

带访问密钥的私有 TCP 访问方式。访问端也需要经过授权配置，适合不希望直接暴露普通公网入口的管理服务。

## XTCP

尝试在支持的网络条件下建立更直接的点对点传输。它依赖双方网络类型、NAT 行为和节点辅助能力，连接结果不如普通中继方式稳定可预测。

## SUDP

带访问密钥的 UDP 访问方式，适用于需要限制访问方的 UDP 服务。可用性和配置字段以客户端与节点支持情况为准。

## 选择速查

| 你的服务 | 优先考虑 |
| --- | --- |
| SSH、RDP、VNC、Minecraft Java | TCP |
| 明确使用 UDP 的游戏或实时服务 | UDP |
| 本地网站或 API | HTTP / HTTPS |
| 只允许指定客户端访问的 TCP 服务 | STCP |
| 只允许指定客户端访问的 UDP 服务 | SUDP |
| 希望尝试点对点传输 | XTCP |

如果无法确定协议，先查看服务的官方文档或监听端口说明，再从通用 TCP 开始测试。[查看实际场景配置](/docs/app/minecraft)
